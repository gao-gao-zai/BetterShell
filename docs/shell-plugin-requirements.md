# Shell 插件需求文档

## 1. 文档信息

- 文档状态：需求初稿
- 目标读者：插件实现者、工具调用编排者、配置和 WebUI 开发者
- 目标：为 Agent 提供一个轻量的普通命令执行能力，并在需要时提供完整、可交互、可持久管理的伪终端能力
- 工具参数和描述设计：见 [`shell-plugin-tool-api.md`](./shell-plugin-tool-api.md)
- 持久级实现研究和第三方库选型：见 [`shell-plugin-implementation-research.md`](./shell-plugin-implementation-research.md)

本文档描述行为需求和对外契约，不限定具体实现语言、PTY 库或操作系统。

## 2. 背景与目标

Agent 在一般任务中通常只需要执行一次命令并读取结果。对于这类场景，工具应保持调用简单、返回紧凑，并且不要求 Agent 预先管理终端会话。

在特殊场景中，Agent 需要处理以下类型的任务：

- 启动并持续操作交互式 CLI 应用
- 多次向同一个 Shell 进程发送命令
- 保留工作目录、环境变量和进程状态
- 查询之前执行的命令及其输出
- 让长时间运行的命令在后台继续执行
- 在命令完成后接收异步结果，而不破坏已有上下文缓存

插件需要同时满足两类需求：

1. **轻量执行**：单次命令调用开箱即用，行为类似现有的 `pwsh` 工具，但支持更细粒度的 Shell、超时、输出长度和前后台控制。
2. **完整伪终端**：提供按 DSH 会话隔离的 PTY 会话管理、命令执行、文本写入、历史查询和结果读取能力。

## 3. 非目标

本插件初期不负责：

- 绕过操作系统或宿主机权限控制
- 执行未被配置白名单允许的 Shell
- 自动解释命令意图或修改 Agent 生成的命令
- 将所有后台输出持续注入上下文
- 替代文件读写工具、网络请求工具或专用代码执行沙箱
- 在多个 DSH 会话之间共享 PTY 进程或命令历史
- 在 DSH 进程重启后恢复、重连或继续使用原有 PTY 会话

## 4. 核心术语

### 4.1 单次执行

不依附于用户可管理的终端会话。每次调用创建一个临时执行上下文，执行结束后回收。它是执行工具的默认模式。

### 4.2 终端会话

由插件管理的、具有独立 PTY 和进程状态的逻辑会话。除单次执行外，一个终端会话对应一个长期存活的 Shell 主进程和一个 PTY；命令作为文本输入到该 Shell 中执行。会话包含：

- 会话名
- 使用的 Shell
- PTY/子进程状态
- 当前工作目录
- 环境和进程状态
- 命令执行记录
- 可供读取的输出记录
- 创建时间、最近活动时间和当前运行状态

终端会话按 DSH Agent/session 隔离。不同 DSH 会话中的 Agent 不得通过会话名访问彼此的终端会话。

v1 的“持久”严格定义为进程内、Agent/session 作用域持久：PTY 和 Shell 主进程可以跨多次工具调用继续存在并保留 cwd、环境和 Shell 状态；当所属 Agent/session 释放或 DSH 进程退出时必须终止。插件不保存可供重启恢复的 PTY 句柄，不支持 DSH 重启后重连原会话。

### 4.3 命令记录

一次 `execute` 模式命令对应一条命令记录。命令记录拥有短 ID，并保存命令输入、状态、开始和结束时间、退出信息以及可读取的输出。

### 4.4 短 ID

用于定位命令记录的短字符串，只允许使用大写字母 `A-Z` 和数字 `0-9`。默认长度为 3 位。随着同一终端会话中的命令数量增多，ID 长度可以增加，以保证在该会话的作用域内不重复。

## 5. 工具总览

插件对 Agent 提供四个工具：

| 工具 | 作用 |
| --- | --- |
| `shell_execute` | 单次执行命令，或在已存在的 PTY 会话中执行命令 |
| `shell_write` | 向已存在的 PTY 会话写入文本或结构化控制输入 |
| `shell_read` | 查询终端会话中的命令记录和合并后的终端输出 |
| `shell_session` | 创建、删除、取消命令，或获取终端会话列表 |

`shell_execute` 支持 `single` 和 `execute` 两种模式；`shell_write` 独立负责写入。执行、写入和管理工具都必须遵守当前 DSH 会话的隔离边界。

## 6. 工具一：执行工具

### 6.1 模式

`shell_execute` 支持两种模式：

1. `single`：单次执行，默认模式。
2. `execute`：在指定且已存在的终端会话的 PTY 中执行命令。

`execute` 必须指定已由 `shell_session` 创建的终端会话名；执行工具不负责隐式创建会话。

### 6.2 `single` 模式

#### 输入要求

- `mode` 可省略，省略时按 `single` 处理。
- 必须提供要执行的命令文本。
- 可以指定白名单内的 Shell。
- 可以指定等待策略：`wait` 或 `background`。
- 可以指定本次调用的超时和最大返回长度，但实际值不得超过对应的用户配置上限。

#### Shell

- 首版目标平台为 Windows，Shell 通过配置的白名单 profile 提供。
- 每个 Shell profile 至少包含名称、可执行文件路径、固定启动参数和是否允许 PTY。
- 工具调用只能引用已配置的 `shell_profile`，不能直接传入任意可执行文件路径。
- 未指定 profile 时使用配置的默认 profile。
- 指定不存在或不允许的 profile 时，调用必须失败，并返回可识别的配置/权限错误。
- `single` 模式可以选择 profile；`execute` 模式不接受 Shell 参数，只使用已创建会话的 profile。
- Shell 参数必须通过配置结构化传递，不能通过未转义字符串拼接造成额外命令注入。

#### 行为

- 每次调用创建独立的临时执行上下文。
- `single` 模式使用 `task_id` 标识可持续跟踪的执行任务；等待模式转后台后必须返回该 ID，主动后台模式也必须返回该 ID。
- 执行完成、最终超时、被取消或发生启动错误后，应回收临时进程及相关资源。
- 等待模式超时只结束当前等待调用，将任务保留为后台任务；后台最终执行上限到期后才按配置终止任务。
- 返回值必须包含执行状态、任务 ID（如果任务仍在后台）、退出信息、等待是否转后台、是否最终超时、是否截断以及受长度限制后的输出。
- 单次模式不产生可通过 `shell_read` 查询的终端会话命令记录；单次任务的状态和取消操作通过 `task_id` 由 `shell_session` 处理。

### 6.3 `execute` 模式

#### 输入要求

- 必须提供 `session_name`。
- 必须提供要执行的命令文本。
- 可以指定等待策略：`wait` 或 `background`。
- 可以指定本次调用的超时和最大返回长度，但不得超过对应的用户配置上限。
- 不接受 Shell 名称、Shell 可执行文件路径或 Shell 启动参数。

#### 会话查找和 Shell 约束

- `session_name` 必须指向当前 DSH 会话中已经存在的终端会话。
- 如果 `session_name` 不存在，调用失败并返回 `SESSION_NOT_FOUND`，提示 Agent 先使用 `shell_session` 创建会话。
- `execute` 不接受 Shell 名称、Shell 可执行文件路径或 Shell 启动参数。
- 终端会话使用的 Shell、固定参数、初始工作目录和环境策略只能在 `shell_session` 创建时确定。
- 会话名在同一个 DSH 会话内不可重复。已存在的名字不能指向第二个终端会话。

#### 并发限制

- 如果目标会话中已有命令正在运行，新的 `execute` 调用必须失败并返回明确的“会话忙”状态。
- `shell_write` 可以在命令运行期间使用，以支持交互式 CLI；实现必须保证同一个 PTY 的写入顺序稳定。
- 不允许通过并发 `execute` 调用破坏命令记录的顺序或混淆输出归属。

#### 状态和输出

- 每次 `execute` 调用都生成一条命令记录和短 ID。
- 插件应在提交给长期 Shell 的命令文本后注入与该命令绑定的唯一结束标记，并监听该标记判断命令结束；结束标记不能被普通命令输出误识别。
- 结束标记应携带命令短 ID、退出码或终止信息，并从对 Agent 暴露的合并输出中按配置决定是否隐藏。
- 命令执行后，工作目录、环境变化和子进程状态应保留在该会话内，具体取决于 Shell/PTY 的实际语义。
- 等待模式返回本次命令的当前完整摘要和受限输出。
- 后台模式立即返回命令已启动的摘要和短 ID，不等待命令结束，也不在同一次调用中返回最终结果。
- 命令在后台结束或超时后，结果应异步注入上下文末尾，并附带清晰提示，说明这是后台命令的完成通知。

### 6.4 等待策略

#### `wait`

- `shell_execute` 的等待调用通常保持等待，直到命令完成、启动失败或被取消。
- 等待时长必须受对应模式的等待上限限制。
- **等待上限到期时，不得终止命令，也不得将命令标记为失败。** 插件应解除当前工具调用对命令的等待，将该任务转为后台跟踪状态，并立即返回一条“等待已结束、命令仍在后台运行”的响应。
- 该响应必须包含终端会话名（如果有）、命令短 ID 或单次任务 ID、命令状态、等待转后台标记，以及后续完成通知说明。
- 命令完成、失败或达到后台任务的最终执行上限后，仍需向 Agent 上下文末尾注入最终结果摘要。
- 等待计时以命令开始或最近一次成功交互写入为基准；`shell_write` 写入会重置对应 PTY 命令的计时。

#### `background`

- 调用提交命令后立即返回，不阻塞 Agent 当前运行。
- 初始返回不得等待最终退出码或完整输出。
- 后台模式具有独立的任务执行上限；该上限到期时命令可被标记为 `timeout`，并按配置终止对应命令进程树。
- 后台任务完成、失败、取消或最终超时后，将一条结果摘要通知注入上下文末尾；等待转后台时只在当前工具响应中返回转后台提示，不额外伪造完成通知。
- 默认只注入短 ID/任务 ID、命令摘要、结束状态、退出码或终止原因；完整输出通过 `shell_read` 获取。
- 注入通知必须带固定提示前缀，例如“后台 Shell 命令结果”。
- 后台任务的并发数量、队列和资源回收应受插件级配置限制。

#### 计时重置

- `shell_write` 每次成功向正在执行命令的 PTY 写入文本或控制输入后，必须重置该命令的活动计时器。
- 重置后的计时器从写入成功时间重新开始，使用该命令当前适用的等待或后台超时上限。
- 写入只能延长命令的计时窗口，不能改变命令的原始模式、短 ID、任务 ID 或最终执行上限配置。
- 单次 `single` 模式没有对应 PTY，不适用写入重置规则。

## 7. 工具二：写入工具

`shell_write` 用于向已存在的终端会话 PTY 输入端写入文本或控制输入。

### 7.1 输入要求

- 必须提供 `session_name`，且目标会话必须已经存在。
- 会话不存在时返回 `SESSION_NOT_FOUND`，不自动创建会话。
- 支持字符串原样写入；换行由调用方显式提供。
- 支持结构化 `control` 字段，用于表达 Ctrl-C、Ctrl-D、Esc 等控制输入，避免依赖字符串转义。
- 不接受 Shell 名称、Shell 可执行文件路径或 Shell 启动参数。
- 写入操作使用独立的写入超时上限，不使用 `wait/background` 执行策略。

### 7.2 行为

- 文本应按会话编码原样写入目标 PTY 输入端。
- `control` 输入必须映射为受支持的终端控制语义，并在工具描述中列出允许的控制值。
- 允许在 `execute` 命令运行期间写入，以支持交互式 CLI；同一个 PTY 的写入顺序必须稳定。
- 每次成功写入文本或结构化控制输入后，必须重置目标命令的活动超时计时；如果当前命令正在等待模式中，等待计时也一并重置。
- 如果目标会话没有正在运行的命令，写入不会创建计时器，也不会影响下一条命令的超时起点。
- 写入后返回写入状态、写入长度、是否重置计时、会话状态以及可选的近期合并输出摘要，但返回值必须受最大返回长度限制。
- `shell_write` 不创建命令记录，也不因任意写入文本而伪造命令记录。

## 8. 工具三：读取工具

`shell_read` 用于读取 PTY 终端会话产生的命令记录和合并后的终端输出。

### 8.1 读取范围

读取工具至少支持以下操作：

1. 查询指定终端会话最近若干次命令的概览列表。
2. 对命令概览列表进行分页查询。
3. 根据终端会话名和短 ID 获取某次命令的返回详情。
4. 查询单条命令当前状态，以支持后台命令尚未结束时的轮询。
5. 对指定命令等待一段时间后再返回，以减少 Agent 高频轮询。
6. 按相对于指定命令的读取模式获取输出：`full` 全量读取或 `incremental` 增量读取。

### 8.2 命令概览列表

列表项至少包含：

- 短 ID
- 命令文本摘要，必要时截断
- 状态：`queued`、`running`、`completed`、`failed`、`timeout`、`cancelled` 等
- 开始时间和结束时间（如果已结束）
- 退出码或终止原因（如果可用）
- 输出是否被截断
- 输出长度或可读的输出摘要

列表默认返回最近几次命令，默认条数和单次最大返回长度均由配置限制。

### 8.3 分页

- 支持基于游标的分页，优先于仅使用页码分页，以避免命令持续增加时发生重复或遗漏。
- 返回 `next_cursor` 或等价字段；没有下一页时返回空值。
- 分页游标必须绑定 DSH 会话、终端会话和查询条件，不能跨范围复用。
- 工具必须限制单页条数和单页总字节数。
- 如果用户配置在查询期间发生变化，应优先保证返回长度不超过新的更小上限。

### 8.4 获取命令返回

根据短 ID 查询时，返回：

- 会话名和短 ID
- 原始命令文本或受限命令文本
- 当前状态
- 开始/结束时间
- 退出码、信号或终止原因
- 本次读取模式：`full` 或 `incremental`
- 合并后的终端输出及其截断标记
- 是否存在更多未返回内容
- 当前输出长度
- 在允许时提供下一次读取位置或输出游标

#### 读取模式

- `full`：相对于指定命令，返回该命令当前已经保存的全部合并终端输出；这是未指定 `read_mode` 时的默认模式。`full` 模式不接受 `offset` 或 `cursor`，如需从上次位置继续读取必须使用 `incremental`。
- `incremental`：相对于指定命令的上一次读取位置，只返回新增的合并终端输出。调用方应提供该命令上一次返回的 `cursor` 或 `offset`；首次增量读取没有游标时，从命令输出起点开始，并返回新的游标。
- 对 `full` 模式，`wait_ms` 在命令状态变化或有任何新增输出时唤醒；对 `incremental` 模式，只有游标之后出现新增输出、命令状态变化或命令结束时唤醒。
- 增量读取不能跨命令复用游标。游标必须绑定 DSH 会话、终端会话、命令短 ID 和输出版本。
- 命令输出发生截断、历史缓冲区淘汰或会话重建导致游标失效时，读取工具必须返回 `INVALID_CURSOR` 或等价状态，并提示 Agent 重新执行全量读取。

#### 等待读取

- 读取请求可以设置 `wait_ms`，表示本次读取调用在返回当前结果前最多阻塞的时间。
- `wait_ms` 为 0 或省略时立即返回当前状态和可读输出。
- 对仍在运行的命令，设置 `wait_ms` 后，读取工具应等待以下任一事件：命令状态发生变化、指定输出模式满足新增输出条件、命令完成/失败/取消，或等待时间到期；事件发生后可以提前返回，不必强行等待完整的 `wait_ms`。
- 等待时间到期不改变命令状态，也不取消命令；工具返回当前已读取内容，并标记 `wait_expired: true`。
- `wait_ms` 必须受读取工具独立等待上限限制，超过上限的调用应拒绝并返回 `TIMEOUT_LIMIT_EXCEEDED`。
- 等待中的读取调用不占用 PTY 的 execute 锁，`shell_write` 仍可向目标会话写入；写入造成新输出或命令状态变化时，应唤醒相关读取请求。

如果命令仍在运行，应返回当前可读取输出和 `running` 状态，而不是把读取超时误报为命令超时。

如果短 ID 不存在、属于其他 DSH 会话、格式非法或已经过期，应返回稳定且可区分的错误类型。

## 9. 工具四：终端管理工具

`shell_session` 负责终端会话的创建、删除、取消命令和列表查询。

### 9.1 创建会话

创建参数至少包括：

- `session_name`：必填，作用域为当前 DSH 会话；只允许 ASCII 字母、数字、`_`、`-`，长度 1-64，且不可重复
- `shell_profile`：必填，引用配置中的 Shell 白名单条目
- 初始工作目录：可选，必须遵守宿主机路径权限和配置限制
- 额外环境变量：可选，必须遵守变量名、数量、长度和敏感信息策略

Shell 白名单条目至少包含：

- 配置名称
- 可执行文件路径
- 固定启动参数
- 是否允许用于 PTY
- 可选的默认工作目录和环境变量策略

Agent 只能选择已配置的 `shell_profile`，不能在工具调用中传入任意可执行文件路径或修改固定启动参数。Shell 白名单始终生效，权限级别不能绕过它。

创建成功后返回：

- 会话名
- 实际 Shell 配置名称和可执行文件路径摘要
- 会话状态
- 创建时间
- 当前工作目录（如果可确定）

如果会话名已存在，不得覆盖或复用已有会话；应返回稳定的重复名称错误。

### 9.2 删除会话

- 删除目标会话及其 PTY 进程和资源。
- 会话中仍有运行命令时，必须终止相关命令进程树，不能无提示地遗留子进程。
- 删除操作应返回会话是否已终止、是否存在强制终止、是否仍有资源清理任务。
- 删除会话时命令历史和输出立即永久删除，不允许通过终端工具继续读取。
- 删除不存在的会话时返回明确的不存在状态，不能伪装成成功。

### 9.3 取消命令或任务

- 取消操作至少接收一种目标：PTY 会话的 `session_name` + `command_id`，或单次后台任务的 `task_id`。
- 对 PTY 命令，默认取消采用优雅终止：向目标命令发送适合当前 PTY 的中断信号，然后终止其进程树并保留 Shell 主进程。
- 对单次后台任务，默认取消采用优雅终止，并在必要时终止该任务的进程树。
- 支持 `force` 选项，用于在优雅终止失败或超时后强制终止目标进程树。
- 取消只能作用于当前 DSH 会话中、状态为 `queued`、`running` 或 `background` 的目标。
- 取消结果必须明确区分已请求、已终止、终止失败和目标已经结束等状态。
- 取消不会删除已经保存的命令输出；读取权限和保留范围仍按对应任务类型处理。

### 9.4 列表查询

列表项至少包括：

- 会话名
- Shell
- 状态：`starting`、`idle`、`busy`、`exited`、`closing`、`error` 等
- 当前工作目录（如果可确定）
- 当前运行命令短 ID（如果有）
- 创建时间
- 最近活动时间
- 命令数量

列表查询同样必须限制返回条数和总返回长度，并遵守 DSH 会话隔离。

## 10. 返回长度和输出截断

### 10.1 两级限制

所有四个工具的返回都必须限制长度，采用两级限制：

1. **用户级最大上限**：由用户配置文件或 WebUI 配置，决定插件允许返回的绝对最大长度。
2. **调用级长度**：Agent 在工具调用中请求的长度，可以小于或等于用户级最大上限，不能超过它。

工具描述中必须写明当前生效的用户级最大上限。该上限至少适用于：

- 单次执行结果
- PTY 执行的同步结果
- 后台完成通知中的摘要
- 单条命令读取结果
- 命令概览列表
- 终端会话列表
- 写入操作的附带输出
- 取消和配置错误响应

### 10.2 截断要求

- 截断时必须返回结构化的 `truncated: true` 或等价字段。
- 应返回实际返回长度和可选的总长度/已丢弃长度。
- PTY 输出按终端显示顺序保存为一个合并流；必须明确 stdout/stderr、Shell 回显和控制序列的合并规则。
- 不得为了满足长度上限而返回无效的半截 JSON、破坏编码的文本或无法识别的状态字段。
- 命令输出应保留在当前终端会话的历史缓冲区中，供 `shell_read` 按需查询和增量读取；会话删除时立即永久删除。
- 输出长度限制应按字节还是字符计算需要统一定义。建议内部按 UTF-8 字节限制，并保证对外文本不会出现非法编码。

## 11. 超时和后台任务配置

### 11.1 配置项

至少需要分别配置：

- single 执行等待模式超时上限，建议默认 30 秒；到期后转后台，不终止命令
- single 后台活动超时上限，建议默认 10 分钟；活动超时后按配置终止任务
- PTY 执行等待模式超时上限，建议默认 30 秒；到期后转后台，不终止命令
- PTY 后台活动超时上限，建议默认 10 分钟；活动超时后按配置终止命令
- PTY 写入超时上限，建议默认 5 秒
- `shell_read` 单次 `wait_ms` 上限，建议默认 30 秒
- single/PTY 任务绝对最长运行时间硬上限；该上限不因写入而重置
- 默认超时
- 同步执行结果最大返回长度，建议默认 16 KiB
- 后台完成通知最大输出长度，建议默认 4 KiB；默认只注入状态摘要，不注入完整输出
- 单条命令历史输出最大保留量
- 单个会话最大历史命令数
- 后台任务最大并发数
- 单个 DSH 会话最大终端会话数
- PTY 空闲回收时间
- DSH 会话结束时的资源清理超时
- 当前 DSH 会话的命令权限级别和命令前缀白名单

上述数值只是首版建议默认值，用户可以通过配置文件或 WebUI 修改，但所有值都必须受更高的插件/宿主硬上限约束。

### 11.2 调用规则

- Agent 可以在调用中请求更短的等待时间、后台活动超时时间、绝对最长运行时间或读取等待时间。
- Agent 请求超过对应配置上限的时间时，调用应被拒绝并返回当前上限，避免 Agent 误以为获得了更长的执行权限。
- 未指定时间时使用对应模式的默认值。
- `shell_execute` 的 `wait` 超时不是命令超时：到期后结束本次等待，将任务转为后台跟踪，不终止命令，并向 Agent 返回转后台提示。
- 后台活动超时或任务绝对最长运行时间到期后，才将任务标记为 `timeout`，并按配置终止对应进程或进程树。
- `shell_read.wait_ms` 到期不是命令超时：只结束读取调用的等待，命令继续按自身生命周期运行。
- `shell_write` 成功写入运行中的 PTY 命令后，重置该命令当前活动计时；该规则不改变任务绝对最长运行时间的边界。
- 进程终止存在延迟时，工具应区分“最终超时已触发”和“进程已确认退出”。

## 12. 命令权限和用户确认

权限级别按 DSH 会话配置；权限级别只决定命令文本是否需要用户确认，Shell profile 白名单始终生效。

### 12.1 权限级别

首版实现以下三个级别，第四级只预留配置枚举，不实现：

1. **完全信任 Agent**：通过 Shell profile 校验后，Agent 可以直接执行命令，不需要额外用户确认。
2. **完全不信任 Agent**：每条命令都必须先获得用户确认，确认前不得启动命令。
3. **命令前缀白名单**：命令匹配白名单中的首段/子命令 token 时自动放行；不匹配时暂停并请求用户确认。
4. **AI 审核**：由另一个 AI 判断命令是否允许执行，首版不实现，但权限配置和接口设计应预留扩展空间。

首版默认权限级别为第一级“完全信任 Agent”。

### 12.2 命令匹配和确认

- 第三级权限按 Shell 解析后的命令首段和子命令 token 匹配，不使用简单的原始字符串前缀匹配。
- 需要确认的命令必须先返回 `pending_confirmation`，在用户作出决定前不得启动命令。
- 用户可以选择：确认执行、拒绝执行，或确认执行并将当前命令前缀加入白名单。
- “确认并加入白名单”会将规则写入配置文件，并同步到 WebUI，默认对该用户的后续 DSH 会话生效。
- 白名单变更必须记录变更来源、时间和规则内容，并支持通过配置文件或 WebUI 撤销。
- 当 Agent 请求 `background` 命令但命中确认规则时，调用可以等待用户确认后再启动；确认等待期间允许阻塞 Agent。
- 被拦截、待确认、拒绝或确认执行的请求应作为审计事件记录，但不作为已执行的普通命令记录，不生成普通命令短 ID。
- 权限错误、确认提示和审计信息同样必须受返回长度限制，并且不得泄漏受保护的命令或环境变量内容。

## 13. Shell 白名单和安全边界

- Shell 白名单是强制安全边界，不得由 Agent 在工具调用中绕过。
- 配置至少应支持：Shell profile 标识、可执行文件路径、固定启动参数、是否允许 PTY、默认工作目录和环境策略。
- `single` 模式和终端会话创建模式都必须校验 Shell profile。
- 会话创建后，`execute` 和 `shell_write` 不允许切换 Shell。
- 应防止通过 Shell 参数、工作目录、环境变量和输入文本绕过白名单。
- 工作目录必须经过规范化和权限校验。
- 环境变量应限制名称、数量和值长度；敏感变量不应出现在工具返回、命令概览或异步通知中。
- 命令、输出、环境和路径日志应考虑敏感信息泄露，配置应支持关闭或脱敏。
- 工具错误不得泄漏超出当前 DSH 会话权限范围的主机信息。

## 14. 配置文件和 WebUI

### 14.1 配置来源

配置支持两种修改入口：

1. 配置文件
2. WebUI

WebUI 修改成功后必须同步写回配置文件。配置文件被外部修改后，插件也应有明确的重新加载机制，例如启动时加载、显式刷新或文件变更监听。

### 14.2 配置校验

- 配置加载时校验类型、范围、白名单和相互依赖关系。
- 非法配置不能静默生效；应返回可诊断错误并使用明确的回退策略。
- 用户配置的最大返回长度必须始终不超过宿主机或插件的硬编码安全上限。
- WebUI 表单必须展示每项配置的有效范围，尤其是超时、输出长度、资源配额、权限级别和并发数。
- 配置更新应记录版本或更新时间，以便排查工具描述与实际配置不一致的问题。

### 14.3 会话配置快照

建议终端会话在创建时记录 Shell、工作目录和关键资源限制的快照。对于会话创建后不能安全修改的属性，后续配置变更不应隐式改变已有会话的 Shell 或进程环境。

## 15. 工具描述与动态配置提示

工具描述会参与 Agent 工具调用缓存，因此不能在会话创建后直接修改工具 schema 或工具描述来反映新的配置上限。

必须实现以下机制：

1. 工具初始描述中写入配置允许的最大上限及其含义。
2. 当会话创建后用户通过配置文件或 WebUI 更新工具相关配置时，不直接修改已有工具描述结构。
3. 在后续上下文末尾注入一条系统可识别的提示，说明配置已更新。
4. 提示至少包含：
   - 生效时间或配置版本
   - 发生变化的配置项
   - 新的有效上限
   - 已存在会话是否受影响
   - Agent 后续调用需要遵守的新限制
5. 新建会话或新建 Agent 会话时，应使用最新配置生成工具描述。
6. 工具实现本身必须在运行时再次校验上限，不能仅依赖工具描述约束 Agent。

提示文本应使用固定前缀，例如：

> Shell 插件配置已更新：后续工具调用的等待超时和最大返回长度上限已变更为……。已有终端会话的 Shell 不变；后续调用将按新上限校验。

## 16. DSH 会话隔离

- 终端会话、命令记录、短 ID、分页游标、后台任务和异步通知都必须绑定 DSH 会话。
- 同名终端会话只要求在单个 DSH 会话内唯一，不同 DSH 会话可以使用相同的会话名。
- Agent 不得通过猜测会话名、短 ID 或分页游标读取其他 DSH 会话数据。
- 后台结果通知必须回到发起该任务的 DSH 会话上下文。
- DSH 会话结束时，默认终止所有终端会话和未完成后台任务，清理 PTY 资源，并立即删除命令历史和输出。
- 清理完成后向 Agent 注入一条清理摘要通知，至少列出被清理的会话名、被终止的运行命令、被取消的后台任务以及已删除的历史范围。
- 异常断开时也必须尽力执行同样的清理和通知；如果上下文已经不可写入，则记录结构化日志。

## 17. 错误和状态模型

- 命令记录状态至少包括：`queued`、`running`、`background`、`completed`、`failed`、`timeout`、`cancelled`。
- `background` 表示命令仍在运行，但当前 `shell_execute` 调用已经结束；它既包括主动后台启动，也包括等待超时后自动转后台。
- `timeout` 只表示后台最终执行上限到期或其他明确的最终超时，不表示 `shell_read.wait_ms` 到期。
- 等待转后台的工具响应使用 `wait_expired: true` 和 `detached_to_background: true`；它不是错误响应。

错误和状态应使用稳定的代码或类型，至少覆盖：

- `SHELL_NOT_ALLOWED`
- `SHELL_ARGUMENTS_NOT_ALLOWED`
- `SESSION_NAME_REQUIRED`
- `SESSION_NAME_DUPLICATE`
- `SESSION_NOT_FOUND`
- `SESSION_BUSY`
- `SESSION_CLOSED`
- `SESSION_START_FAILED`
- `COMMAND_START_FAILED`
- `COMMAND_TIMEOUT`
- `COMMAND_CANCELLED`
- `COMMAND_NOT_FOUND`
- `INVALID_COMMAND_ID`
- `INVALID_CURSOR`
- `OUTPUT_LIMIT_EXCEEDED`
- `TIMEOUT_LIMIT_EXCEEDED`
- `READ_WAIT_LIMIT_EXCEEDED`
- `TASK_NOT_FOUND`
- `TASK_CANCELLED`
- `COMMAND_WAIT_DETACHED`
- `CONFIG_INVALID`
- `RESOURCE_LIMIT_EXCEEDED`

每个错误返回应包含：错误代码、面向 Agent 的简短说明、是否可重试，以及必要时的修复建议。错误响应也必须遵守最大返回长度限制。

## 18. 建议的返回结构

以下为行为示例，不要求字段名必须完全一致。

### 18.1 单次执行完成

```json
{
  "mode": "single",
  "status": "completed",
  "task_id": null,
  "exit_code": 0,
  "timed_out": false,
  "wait_expired": false,
  "output": "...",
  "truncated": false,
  "duration_ms": 128
}
```

### 18.2 等待超时转后台

```json
{
  "mode": "single",
  "task_id": "T00A",
  "status": "background",
  "background": true,
  "wait_expired": true,
  "detached_to_background": true,
  "message": "等待时间已到，命令未被终止，现已转为后台运行；完成后将注入最终结果通知。"
}
```

PTY `execute` 模式使用 `session_name` + `command_id` 代替 `task_id`。

### 18.3 主动后台启动

```json
{
  "mode": "execute",
  "session_name": "build",
  "command_id": "00A",
  "status": "background",
  "background": true,
  "wait_expired": false,
  "message": "命令已在终端会话中后台运行，完成后将注入结果通知。"
}
```

### 18.4 后台完成通知

```json
{
  "notification_type": "shell_background_result",
  "session_name": "build",
  "command_id": "00A",
  "command_preview": "npm run build",
  "status": "completed",
  "exit_code": 0,
  "termination_reason": null,
  "output_available": true
}
```

后台完成通知必须包含发起任务的标识：single 使用 `task_id`，PTY 使用 `session_name` + `command_id`；默认不携带完整输出，Agent 需要内容时通过相应读取接口查询。

### 18.5 读取命令的增量结果

```json
{
  "operation": "command_output",
  "session_name": "build",
  "command_id": "00A",
  "status": "running",
  "read_mode": "incremental",
  "wait_ms": 30000,
  "wait_expired": false,
  "output": "new output...",
  "offset": 256,
  "next_cursor": "...",
  "truncated": false
}
```

`read_mode: "full"` 时，`output` 表示指定命令当前保存的全量输出；`read_mode: "incremental"` 时，`output` 只表示上一次游标之后新增的内容。

### 18.6 会话命令概览

```json
{
  "session_name": "build",
  "items": [
    {
      "command_id": "00A",
      "command_preview": "npm run build",
      "status": "completed",
      "started_at": "...",
      "finished_at": "...",
      "exit_code": 0,
      "output_available": true
    }
  ],
  "next_cursor": null,
  "truncated": false
}
```

## 19. 资源和保留策略

为避免长时间运行或高输出命令耗尽资源，至少需要配置：

- 单个命令的最大输出保留量
- 单个终端会话的最大历史命令数
- 单个 DSH 会话的最大终端会话数
- 后台任务最大并发数
- PTY 空闲回收时间
- DSH 会话结束时的资源清理超时
- 单个会话最大运行时间
- 单个写入请求最大长度
- 进程树终止和孤儿进程清理策略

达到资源上限时，应返回明确错误或执行淘汰策略，并确保淘汰不会删除正在运行命令的必要状态。

## 20. 可观测性

建议记录以下事件：

- 会话创建、删除和异常退出
- Shell 白名单拒绝
- 命令提交、完成、失败、等待转后台、最终超时和取消
- 读取等待开始、读取到新输出和读取等待到期
- 后台任务开始和结果通知注入
- 输出截断
- 配置更新和配置校验失败
- 资源限制触发

日志应包含 DSH 会话标识、终端会话名、命令短 ID 和事件时间，但应对命令文本、环境变量和输出中的敏感数据进行脱敏或按配置禁用。

## 21. 验收标准

### 21.1 单次执行

- 不指定模式时可以使用默认 Shell profile 执行命令。
- 指定未配置或不允许的 Shell profile 时调用失败。
- 可以分别配置等待和后台执行。
- 可以配置本次调用的等待时间、后台最终执行上限和最大输出长度，并且无法超过用户级上限。
- 等待时间到期时命令不会被终止，而是返回 `task_id` 并转为后台运行。
- `shell_session` 可以按 `task_id` 取消 single 后台任务。
- 输出过长时能明确标记截断。
- 后台命令完成、失败、取消或最终超时后会收到上下文末尾摘要通知。
- 命令权限级别生效时，未获确认的命令不会启动。

### 21.2 PTY 会话执行和写入

- 可以使用 `shell_session` 创建唯一命名的终端会话。
- 指定不存在的会话执行命令或写入内容时失败，不会自动创建。
- 会话创建后不能通过 `shell_execute` 或 `shell_write` 修改 Shell profile。
- 同一会话有命令运行时，第二个 `execute` 调用会得到会话忙错误。
- `shell_write` 可以向交互式 CLI 输入原始文本、换行和结构化控制输入。
- `shell_write` 成功写入运行中命令后，会重置该命令的活动计时。
- 会话中的工作目录和进程状态按长期 Shell/PTY 语义持续存在，并可以跨多次工具调用继续使用。
- execute 等待时间到期时只转入后台，不终止当前命令；后台最终执行上限到期或主动取消时才终止命令进程树，并保留 Shell 主进程和终端会话。
- 所属 Agent/session 正常释放时，插件会终止其所有 PTY 和后台任务、等待进程树停稳、清理输出和命令历史；不会影响其他 owner。
- DSH 正常退出时会等待所有终端资源清理完成；DSH 异常退出时必须依靠 Windows Job Object `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` 或等价 OS 级所有权保证子进程不会遗留。
- DSH 再次启动后不会列出、恢复或重连退出前的终端会话。

### 21.3 读取和短 ID

- 每条会话命令都有唯一短 ID。
- 短 ID 初始为 3 位，只包含大写字母和数字，并能在命令增多后扩展长度。
- 可以分页获取最近命令概览。
- 可以按短 ID 获取命令状态和合并终端输出。
- `read_mode: full` 可以读取相对于指定命令的当前全量输出。
- `read_mode: incremental` 可以按命令绑定的 offset/cursor 读取新增输出。
- 设置 `wait_ms` 后，读取工具会阻塞到有新输出、命令状态变化、命令结束或等待到期。
- `wait_ms` 到期只返回 `wait_expired: true`，不会改变或取消命令。
- 错误短 ID、无效游标和其他 DSH 会话的短 ID 不会泄露数据。

### 21.4 配置和缓存

- 配置文件和 WebUI 都可以修改配置。
- WebUI 修改会同步写入配置文件。
- 修改后的上限会在运行时强制生效。
- 已创建 Agent 会话不通过修改工具 schema 破坏缓存，而是通过上下文末尾提示获得新配置。
- 新旧配置下的返回长度、超时、权限级别和会话影响范围可被明确验证。

## 22. 后续设计待确认事项

以下内容已经有方向，但实现前仍需要定稿：

1. Shell profile 的具体配置文件格式，以及首批实际允许的可执行文件路径。
2. 建议默认值对应的插件硬上限和各项资源配额。
3. 合并终端流中 stdout/stderr、Shell 回显、控制序列和编码转换的精确规则。
4. Windows 下优雅终止命令进程树、保留 Shell 主进程的具体实现和失败回退策略。
5. 控制输入支持的完整枚举，以及 Ctrl-D、Esc 等输入在 PowerShell 中的最终语义。
6. 短 ID 和 single `task_id` 的生成算法、碰撞处理及唯一性作用域。
7. 后台结果通知的队列、顺序和 Agent 已结束时的处理方式。
8. 配置热加载的触发方式，以及 WebUI 写配置失败时的回滚策略。
9. 用户确认 UI 与工具调用之间的协议，以及确认超时、拒绝和 DSH 会话结束时的处理。
10. 第四级 AI 审核权限的预留接口；首版不实现审核逻辑。
11. 是否在首版支持 PTY 终端尺寸调整；当前已确定优先支持文本和结构化控制输入。
12. single 后台任务除取消外是否需要独立状态查询接口；当前只要求通过完成通知获知最终结果。

## 23. 实现优先级建议

### P0：最小可用版本

- `shell_execute` 的 `single` 模式
- Windows Shell profile 白名单
- 等待超时转后台和后台最终执行上限
- 返回长度限制和截断标记
- `shell_session` 的创建、列表、删除和任务取消

- DSH 会话隔离和会话结束清理
- 第一级完全信任权限模式

- 配置更新提示

- 进程树可观测性
